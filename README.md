# Вадим Родберг: продуктовый дизайн и автоматизация

Готовый статический коммерческий лендинг на Astro 7 и TypeScript. Без React, CMS, сервера заявок, базы данных и счётчиков. Весь основной контент находится в HTML. Шрифт Manrope с кириллицей, изображения и скрипты обслуживаются локально, без запросов к сторонним сервисам при загрузке страницы.

Публичная версия: https://rdbrg.github.io/product-design-sale-site/

## Запуск

Требуется Node.js 24 LTS и npm. Выполняйте команды в каталоге проекта.

```powershell
npm ci
npm run dev
```

Адрес по умолчанию: http://localhost:4321/. Если порт занят, Astro покажет другой адрес. Для просмотра готовой сборки вместо режима разработки:

```powershell
npm run build
npm run preview
```

`dist/` содержит статический результат. Не открывайте `index.html` через `file://`: для модульных скриптов и корректных путей нужен HTTP-сервер.

## Проверки

```powershell
npx playwright install chromium webkit
npm run build
npm test
npm run check:links
npm run check:publication
npm audit
```

`npm test` автоматически запускает локальный preview, если порт 4321 свободен, либо использует уже запущенный сервер. Перед тестированием обновляйте сборку. Проверяется именно статическая версия.

Результат проверки при передаче:

- Сборка и проверка типов: без ошибок и предупреждений.
- Playwright: 23 успешных теста, 1 намеренно пропущенный тест системного буфера в WebKit. Настоящий буфер Windows проверен в Chromium; успешная ветка API и ручной fallback проверены в обоих движках.
- Размеры: 360, 390, 768, 1024 и 1440 px в Chromium и WebKit. Горизонтального переполнения нет.
- Проверены меню, Escape, возврат фокуса, якоря, раскрытия с клавиатуры, ссылки, копирование, события аналитики и `prefers-reduced-motion`.
- axe-core: нет нарушений в автоматических проверках WCAG 2 A/AA и 2.1 AA при ширинах 390 и 1440 px с раскрытыми подробностями и FAQ. Автотест не заменяет проверку реальным скринридером.
- Ошибок JavaScript и ошибок загрузки ресурсов в браузерах не обнаружено. Внешних запросов при загрузке страницы нет.
- Без JavaScript остаются контент, навигация, нативные раскрытия, прямые контакты и текст для ручного копирования.
- Все внешние HTTPS-ссылки лендинга ответили HTTP 200. Email проверен как `mailto:`, тестовые сообщения не отправлялись.
- `npm audit`: 0 известных уязвимостей на момент проверки.

Локальные скриншоты находятся в `artifacts/screenshots/`: название включает браузер, ширину и секцию (`hero`, `services`, `experience`, `contact`, `full`). Для каждого движка и ширины сохранены первый экран, ключевые секции и полная страница. HTML-отчёт последнего тестирования: `playwright-report/index.html`. Артефакты проверки не включаются в репозиторий и пересоздаются командой `npm test`.

Проверка публикации создаёт отдельную `.verification-build/`. В ней URL существующего портфолио используется исключительно как тестовый адрес для проверки canonical, OG, sitemap и путей подпапки. **Не публикуйте эту папку.** Она не меняет `dist/` и не назначает адрес новому сайту.

## Публикация

Сайт опубликован через GitHub Pages. Workflow `.github/workflows/deploy-pages.yml` автоматически пересобирает и размещает `main` по адресу https://rdbrg.github.io/product-design-sale-site/. Node.js требуется только для сборки, а не на хостинге готового сайта.

1. Определите реальный HTTPS-адрес лендинга. Если сайт расположен в подпапке, укажите полный адрес с этой подпапкой.
2. Установите `SITE_URL` в окружении сборки. Для локального PowerShell можно ввести адрес через команду ниже.
3. Выполните `npm ci`, затем `npm run build`.
4. Размещайте только содержимое `dist/` по выбранному адресу. Для сервисов сборки команда: `npm run build`, каталог результата: `dist`.
5. Настройте HTTPS и проверьте публичную страницу, favicon, Telegram, email, `/sitemap.xml` и `/robots.txt` с учётом выбранной подпапки.
6. Проверьте превью ссылки после публикации. Некоторые сервисы кэшируют Open Graph: при обновлении изображения может потребоваться обновить их кэш.

```powershell
$env:SITE_URL = Read-Host 'Введите реальный HTTPS-адрес лендинга'
npm run build
```

Конфигурация автоматически вычисляет базовый путь, canonical, абсолютные `og:url` и `og:image`, содержимое sitemap и ссылку на sitemap в robots. Валидация отклоняет небезопасную схему, параметры запроса и фрагменты.

Без `SITE_URL` сайт полностью работает локально. Canonical, абсолютный OG-адрес и OG-изображение не выводятся; sitemap остаётся пустым и не рекламируется в robots. Выдуманного домена в `dist/` нет. Перед публичным размещением обязательно пересоберите с реальным адресом.

Файл `public/.nojekyll` позволяет раздавать `_astro/` на GitHub Pages без обработки Jekyll. Не загружайте на хостинг исходники, `node_modules`, тестовые отчёты, `.verification-build/` или временные файлы.

## Аналитика

Счётчик не подключён, данные никуда не отправляются. Готовый интеграционный интерфейс: событие браузера `rodberg:analytics` с объектом `detail`.

| Событие `detail.name` | Дополнительные поля |
| --- | --- |
| `primary_cta` | `placement`: `header`, `hero` или `contact` |
| `service_contact` | `service`: ID услуги |
| `case_open` | `case`: ID кейса |
| `template_copy` | `result`: `success` или `manual` |
| `telegram_click` | Контекст кнопки, если есть |
| `email_click` | Нет |

Один клик основного CTA в Telegram создаёт два события: контекстное `primary_cta` и канальное `telegram_click`. При подключении аналитики выберите одно событие для счётчика конверсий, чтобы не учитывать обращение дважды.

Пример точки подключения без включения стороннего сервиса:

```typescript
window.addEventListener('rodberg:analytics', (event) => {
  const detail = (event as CustomEvent).detail;
  // Передайте разрешённые поля в выбранный счётчик после его настройки.
});
```

События содержат только фиксированные идентификаторы. Текст обращения, буфер обмена, email посетителя и другие персональные данные в события не включаются. Добавление аналитики требует отдельного решения о провайдере, идентификаторе и необходимых мерах конфиденциальности.

## Перед публикацией

- Выбрать хостинг и окончательный URL, затем собрать сайт с `SITE_URL`.
- Подтвердить нужную налоговую формулировку для цен и при необходимости заполнить `taxNote`.
- Если аналитика нужна на старте, предоставить выбранный сервис и идентификатор счётчика. Без аналитики сайт уже работает.

Фотография, юридические реквизиты и форма заявки для этой версии не требуются и не подставлены вымышленными данными.
